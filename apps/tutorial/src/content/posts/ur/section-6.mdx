Web scraping ڈیٹا سائنس دانوں اور ڈویلپرز کے لیے ایک لازمی مہارت بن چکی ہے، لیکن اس کے مقابلے میں ویب سائٹ مالکان نے بھی اپنے دفاعی طریقے ترقی دے لیے ہیں۔ یہ باب Web scraping کے دفاعی ہتھکنڈوں کی اس بلی اور چوہے کی دوڑ کا جائزہ لیتا ہے اور یہ بتاتا ہے کہ ان سے مؤثر طور پر کیسے نمٹا جائے۔

## باب 11: دشمن کی صفوں کے پیچھے

اس باب میں آپ "CryptoDefend Exchange" سے نمٹیں گے — ایک فرضی cryptocurrency exchange پلیٹ فارم جو نہیں چاہتا کہ اس کا ڈیٹا آسانی سے حاصل کیا جائے۔ بہت سی مالیاتی سائٹس کی طرح، CryptoDefend قیمتوں کے ڈیٹا، trading volumes، اور market trends کی خودکار جمع آوری کو روکنے کے لیے مختلف دفاعی اقدامات نافذ کرتا ہے۔

ہمارا چیلنج ان دفاعی تدابیر کو ایک قابو میں رکھے گئے ماحول میں نقل کرتا ہے، تاکہ آپ یہ کر سکیں:

- اُن عام اینٹی اسکریپنگ طریقہ کار کو سمجھنا جو زیادہ قدر رکھنے والے اہداف استعمال کرتے ہیں
- کامیاب ڈیٹا اخذ کرنے کے لیے عملی حکمت عملیاں تیار کرنا
- ثابت قدمی اور تکنیکی چیلنجوں کے درمیان توازن قائم کرنا

## حقیقی دنیا میں کثیر سطحی دفاع

آج کے اینٹی اسکریپنگ ہتھیاروں میں کئی جدید تکنیکیں شامل ہیں:

### Rate Limiting اور IP Blocking

سب سے بنیادی دفاع اب بھی درخواستوں کی تعداد پر نظر رکھنا اور حد سے تجاوز کرنے والے IPs کو بلاک کرنا ہے:

```javascript
// Simplified rate limiting concept
const requestCounts = {};

app.use((req, res, next) => {
  const ip = req.ip;
  requestCounts[ip] = (requestCounts[ip] || 0) + 1;
  
  if (requestCounts[ip] > THRESHOLD) {
    return res.status(429).send('Too Many Requests');
  }
  next();
});
```

Rate limiting سے نمٹنے کے لیے، آپ کے scraper کو یہ کرنا ہوگا:

- درخواستوں کے درمیان وقفے نافذ کرنا
- robots.txt کی ہدایات کا احترام کرنا
- بڑے پیمانے پر scraping کرتے وقت IPs کی rotation پر غور کرنا

### CAPTCHAs اور تعاملی چیلنجز

CAPTCHAs ایسے کام پیش کرتے ہیں جو انسانوں کے لیے آسان مگر bots کے لیے مشکل ہوتے ہیں۔ جدید CAPTCHAs جیسے reCAPTCHA v3 پس منظر میں غیر مرئی انداز سے بھی کام کرتے ہیں اور صارف کے رویّے کا تجزیہ کرتے ہیں:

```html
<!-- Example CAPTCHA implementation -->
<form>
  <div class="g-recaptcha" data-sitekey="your-site-key"></div>
  <button type="submit">Submit</button>
</form>
```

CAPTCHAs سے گزرنے کے لیے یہ طریقے شامل ہو سکتے ہیں:

- CAPTCHA solving services کا استعمال (اگرچہ اس میں اخلاقی پہلو شامل ہیں)
- انسانی انداز کے مشابہ رویّے کی نقالی کے لیے browser automation سے فائدہ اٹھانا
- یہ تسلیم کرنا کہ کچھ مواد شاید ناقابلِ رسائی ہی رہے

### Behavioral Analysis اور Fingerprinting

جدید دفاعی نظام bots کی شناخت کے لیے mouse movements، scrolling patterns، اور device characteristics کو ٹریک کرتے ہیں:

```javascript
// Simplified fingerprinting concept
function collectFingerprint() {
  return {
    userAgent: navigator.userAgent,
    screenResolution: `${screen.width}x${screen.height}`,
    timezone: Intl.DateTimeFormat().resolvedOptions().timeZone,
    language: navigator.language,
    // Many more signals in production systems
  };
}
```

ان تکنیکوں کا مقابلہ کرنے کے لیے درکار ہے:

- Headless browsers جو انسانی طرز کے مشابہ رویّے کی نقالی کر سکیں
- interaction patterns میں بے قاعدہ تغیر پیدا کرنا
- cookies اور session data کو مستقل انداز میں سنبھالنا

### Dynamic Content اور HTML Obfuscation

بہت سی سائٹس JavaScript کے ذریعے مواد render کرتی ہیں یا element IDs اور class names کو بے ترتیب بنا دیتی ہیں:

```html
<!-- Yesterday's HTML -->
<div class="product-price">$99.99</div>

<!-- Today's HTML after obfuscation -->
<div class="_a7b92f3e">$99.99</div>
```

اس کے لیے آپ کے scraper کو یہ کرنا ہوگا:

- Playwright یا Puppeteer جیسے مکمل browser environments استعمال کرنا
- عین selectors کے بجائے مواد کے pattern پر توجہ دینا
- parsing کی زیادہ مضبوط حکمت عملیاں نافذ کرنا

## اخلاقی اور قانونی پہلو

اگرچہ یہ باب دفاعی نظاموں سے نمٹنے کی تکنیکیں متعارف کراتا ہے، لیکن یہ نوٹ کرنا ضروری ہے کہ:

- ضرورت سے زیادہ scraping ویب سائٹ کی کارکردگی کو نقصان پہنچا سکتی ہے
- Terms of Service اکثر واضح طور پر scraping کو منع کرتی ہیں
- بعض دائرہ ہائے اختیار میں غیر مجاز رسائی سے متعلق قوانین موجود ہیں

تعلیمی مقاصد کے لیے، ہم یہ تجویز کرتے ہیں:

- production sites پر scraping سے پہلے robots.txt چیک کرنا
- درخواستوں کے درمیان معقول وقفے نافذ کرنا
- جب کارکردگی اہم ہو تو API کے اختیارات پر غور کرنا
- مناسب مواقع پر قابلِ شناخت user agent استعمال کرنا

## چیلنج کی حکمت عملی

باب 11 میں ہمارا CryptoDefend exchange ایسے حقیقت پسندانہ چیلنجز پیش کرتا ہے جن کا سامنا آپ کو مالیاتی ڈیٹا جمع کرتے وقت ہو سکتا ہے۔ آپ کو ان چیزوں سے نمٹنا ہوگا:

- price API endpoints پر Rate limiting
- trading data تک رسائی کے لیے سادہ verification puzzles
- market charts جو صرف JavaScript کے ذریعے render ہوتے ہیں
- بے ترتیب selectors جو ہر وزٹ کے درمیان بدل جاتے ہیں

مقصد یہ ہے کہ ان طریقہ کار کو سمجھا جائے اور اپنے ڈیٹا جمع کرنے کے toolkit کے لیے عملی تکنیکیں تیار کی جائیں۔

```typescript

  for (const url of urls) {
```
