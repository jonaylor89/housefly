हमारी hands-on web crawling tutorial श्रृंखला के अंतिम भाग में आपका स्वागत है। पारंपरिक पाठ के बजाय, हम एक अलग तरीका अपना रहे हैं। इस भाग के लिए, मैंने `./apps/metascraper` directory में Housefly Metascraper बनाया है—एक crawler जो दिखाता है कि हमने जो कुछ सीखा है, उसे वास्तविक परिस्थितियों में कैसे लागू किया जाए।

Metascraper यह दिखाता है कि हमारी चरण-दर-चरण यात्रा—सरल static HTML को scrape करने से लेकर, JavaScript-rendered content में navigate करने, APIs के साथ interaction करने, और crawling defenses को पार करने तक—आख़िरकार ऐसे tool में बदलती है जो **बड़े पैमाने पर असंरचित, विविध, और अराजक web** को संभाल सकता है।

हम यह समझेंगे कि तरह-तरह की websites पर कैसे crawl किया जाए—बिना पहले से यह जाने कि किस प्रकार की data structures मिलने वाली हैं—और **AI-assisted parsing**, **dynamic schema detection**, तथा **हज़ारों (या लाखों) pages तक scale करने** के लिए आवश्यक तकनीकों का परिचय देंगे, वह भी बिना प्रणाली को बिखरने दिए।

## "Unstructured" और "Large-Scale" का वास्तव में क्या मतलब है?

पिछले भागों में हमें अक्सर यह पता होता था:
- हम किन sites को लक्ष्य बना रहे थे।
- हमें कौन-सा डेटा चाहिए था (जैसे tables, lists, JSON responses)।
- हमें कितने pages पर जाना था।

लेकिन बड़े पैमाने पर असंरचित crawling में:
- websites बहुत अलग-अलग होती हैं: कुछ सुव्यवस्थित होती हैं, तो कुछ अनियमित formatting वाले blogs होते हैं।
- paths और URLs का अनुमान लगाना कठिन होता है।
- schema असंगत होता है या मौजूद ही नहीं होता।
- हम **हज़ारों pages crawl करना** चाहते हैं, संभवतः **कई domains** में फैले हुए।

सोचिए:
- academic websites से डेटा एकत्र करने वाले research crawlers।
- विषय-विशेष ज्ञान के लिए blogs को index करने वाले AI assistants।
- search engines जिन्हें पूरे public internet पर सामान्यीकृत होकर काम करना पड़ता है।

यही web crawling का अंतिम boss है।

## Part 1: Large-Scale Crawling के लिए Architecture तैयार करना

Parsing की चिंता करने से पहले, आइए बात करें कि अपने crawler को बड़े पैमाने पर कैसे ले जाया जाए।

### Design Patterns

बड़े पैमाने का crawler बनाने के लिए आपकी architecture ऐसी होनी चाहिए:
- **Queue-driven:** लंबित URLs को रखने के लिए message queue (जैसे Redis, RabbitMQ, या Kafka) का उपयोग करें।
- **Worker-based:** crawlers को अलग worker processes में बाँटें, जो queue से काम लें और jobs को स्वतंत्र रूप से process करें।
- **Deduplicated:** एक fingerprinted index (जैसे URL या HTML content का SHA1) बनाए रखें ताकि एक ही page को दोबारा process न करना पड़े।
- **Resumable:** crawl state को persist करें ताकि crash होने पर पुनर्प्राप्ति हो सके।

## Part 2: 2025 की उन्नत तकनीकें

### Residential Proxies

बड़े पैमाने की scraping में सबसे महत्वपूर्ण प्रगतियों में से एक है **residential proxies** का उपयोग। datacenter IPs के विपरीत, जिन्हें websites आसानी से पहचानकर block कर सकती हैं, residential proxies आपके requests को वास्तविक उपभोक्ता IP addresses के माध्यम से route करते हैं, जिससे आपका scraper एक वैध user जैसा दिखाई देता है।

### AI-Powered Autonomous Agents

2025 की सबसे क्रांतिकारी प्रगति है **agentic scraping**। हर site format के लिए scrapers को hard-code करने के बजाय:

- vision capabilities वाले LLMs पहले कभी न देखे गए layouts को समझकर उनसे डेटा निकाल सकते हैं
- AI agents मानव browsing patterns की नकल करते हुए जटिल sites पर स्वायत्त रूप से navigate कर सकते हैं
- adaptive parsing, code updates की आवश्यकता के बिना, layout changes के अनुसार अपने-आप समायोजित हो जाती है

## Part 4: डेटा का संग्रह, indexing, और search

आप **बहुत सारा विषम प्रकार का डेटा** इकट्ठा करेंगे। अपने उद्देश्यों और डेटा कितना संरचित है, इसके आधार पर storage चुनें।

### Storage Strategies

- **PostgreSQL** या **SQLite**: संरचित tabular data के लिए सर्वोत्तम, जहाँ आपको schema पता हो (जैसे articles, prices, timestamps)। आप indexes, foreign keys, और full-text search (FTS) का उपयोग कर सकते हैं।
- **MongoDB** या **Elasticsearch**: semi-structured या लचीले data formats जैसे JSON blobs के लिए बेहतरीन, जहाँ schema records के बीच बदल सकता है।
- **S3 / IPFS / File System**: raw HTML snapshots, images, PDFs, और बड़े binary files के लिए आदर्श। metadata को database में रखें और file location से link करें।

primary keys के रूप में UUIDs या URL hashes का उपयोग करें ताकि आप de-duplicate कर सकें और पहले crawl की जा चुकी items को track कर सकें।

### इसे Searchable बनाना

डेटा store हो जाने के बाद, आप content को **खोजना और query करना** चाहेंगे।

विकल्पों में शामिल हैं:

- **PostgreSQL FTS (Full-Text Search)**: मजबूत keyword search capabilities को ranking के साथ बनाने के लिए `tsvector` और `tsquery` का उपयोग करें।
- **Typesense** या **Meilisearch**: हल्के, schema-flexible full-text search engines, जो तेज indexing और fuzzy search के लिए उपयुक्त हैं।
- **Elasticsearch**: अधिक जटिल search उपयोग-मामलों या logs के लिए सर्वोत्तम, जिसमें शक्तिशाली filtering और analytics मिलती है।

आपको निम्न fields को index करना चाहिए:
- Title
- Author
- Date published
- Keywords या tags (यदि निकाले गए हों)
- Main content
- Domain / source

### Embeddings के साथ Semantic Search

अधिक गहरी समझ और retrieval के लिए (सिर्फ keywords से आगे), **text embeddings** का उपयोग करें:

1. OpenAI के `text-embedding-3-small` जैसे model या `bge-small-en` जैसे open-source alternatives का उपयोग करें।
2. अपने crawled content को embedding vectors में बदलें।
3. इन्हें किसी **vector database** में store करें, जैसे:
   - **Qdrant**
   - **Weaviate**
   - **Pinecone**
   - **FAISS** (local / in-memory उपयोग के लिए)

इससे ऐसे semantic queries संभव होते हैं:
> "मुझे ऐसे articles दिखाइए जहाँ कोई व्यक्ति ठंडे मौसम वाले क्षेत्रों में साइकिल-अनुकूल शहरी विकास की बात करता हो।"

query embedding की stored embeddings से तुलना करके, आपका crawler एक knowledge engine बन जाता है।

### Metadata और Enrichment

अंत में, अपने डेटा को अतिरिक्त metadata से समृद्ध करें:

- **Language detection** (जैसे `langdetect` या fastText के साथ)।
- zero-shot models या fine-tuned classifiers का उपयोग करके **content category classification**।
- लोगों, organizations, और places को निकालने के लिए **Named Entity Recognition (NER)**।
- content या source के आधार पर **Geotagging**।

इसे मुख्य डेटा के साथ store करें ताकि बाद में आप इसके आधार पर filter और sort कर सकें।

## Part 5: Search-Driven Discovery Crawlers

बड़े पैमाने की crawling के लिए सबसे उन्नत तरीका URLs से शुरू ही नहीं होता—इसके बजाय, यह **search queries** से शुरू होता है।

SearchXNG और Perplexity जैसे tools से प्रेरित, Metascraper एक search-first strategy दिखाता है, जिसमें crawler:

1. seed URL list के बजाय किसी **topic या question** से शुरुआत करता है
2. प्रासंगिक pages को real-time में खोजने के लिए search engine APIs का उपयोग करता है
3. search results के आधार पर अपनी crawl queue को dynamic रूप से बनाता है
4. ज्ञान-विस्तार के लिए citations और references का बुद्धिमानी से अनुसरण करता है

यह तरीका कई लाभ देता है:

- **Targeted Exploration**: exhaustive crawling के बजाय, आप केवल उन्हीं pages पर जाते हैं जिनमें प्रासंगिक जानकारी होने की संभावना है
- **Up-to-date Results**: हर crawl वर्तमान search results के साथ नए सिरे से शुरू होता है
- **Domain-agnostic**: पहले से परिभाषित sites या URL patterns तक सीमित नहीं
- **Intention-driven**: यह उस तरीके के अनुरूप है जिससे मनुष्य वास्तव में विषयों पर शोध करते हैं

Metascraper का search-driven mode यह दिखाता है कि search APIs, prioritization algorithms, और context-aware extraction को मिलाकर dynamically discovered content से knowledge graphs कैसे बनाए जाएँ, वह भी बिना पहले से यह जाने कि आप किन URLs पर जाएँगे।
