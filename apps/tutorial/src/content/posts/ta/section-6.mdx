தரவு அறிவியலாளர்களுக்கும் developers-க்கும் Web scraping இன்றியமையாத திறனாக மாறியுள்ளது; அதே நேரத்தில் website உரிமையாளர்களும் தங்களுடைய பாதுகாப்பு முறைகளை அதற்கு ஏற்றவாறு மேம்படுத்தியுள்ளனர். இந்த அத்தியாயம் web scraping பாதுகாப்புகளின் பூனை-எலி போட்டியையும், அவற்றை எவ்வாறு பயனுள்ளதாக சமாளிப்பது என்பதையும் ஆராய்கிறது.

## அத்தியாயம் 11: எதிரி வரிகளின் பின்னால்

இந்த அத்தியாயத்தில், நீங்கள் "CryptoDefend Exchange" - தன் தரவை எளிதில் அணுக அனுமதிக்க விரும்பாத ஒரு கற்பனை cryptocurrency exchange platform-ஐ எதிர்கொள்வீர்கள். பல நிதி தளங்களைப் போலவே, CryptoDefend விலைத் தரவு, வர்த்தக அளவுகள், மற்றும் சந்தைப் போக்குகள் ஆகியவற்றை தானியக்கமாக சேகரிப்பதைத் தடுக்க பலவிதமான பாதுகாப்பு நடவடிக்கைகளை செயல்படுத்துகிறது.

எங்கள் சவால் இந்த பாதுகாப்புகளை கட்டுப்படுத்தப்பட்ட சூழலில் உருவகப்படுத்துகிறது; இதன் மூலம் நீங்கள்:

- உயர்ந்த மதிப்புள்ள இலக்குகள் பயன்படுத்தும் பொதுவான anti-scraping செயல்முறைகளைப் புரிந்துகொள்ளலாம்
- வெற்றிகரமான தரவு பிரித்தெடுப்புக்கான நடைமுறை உத்திகளை உருவாக்கலாம்
- விடாமுயற்சி மற்றும் தொழில்நுட்பச் சவால்கள் ஆகியவற்றுக்கு இடையில் சமநிலையைப் பேணலாம்

## நிஜ உலகில் பல அடுக்கு பாதுகாப்புகள்

இன்றைய anti-scraping ஆயுதக்களத்தில் பல நுணுக்கமான உத்திகள் உள்ளன:

### Rate Limiting மற்றும் IP தடுப்பு

அடிப்படை பாதுகாப்பாக இன்னும் இருப்பது, request நிகழ்தகவை கண்காணித்து, நிர்ணயிக்கப்பட்ட வரம்புகளை மீறும் IP-களைத் தடுக்குவதுதான்:

```javascript
// Simplified rate limiting concept
const requestCounts = {};

app.use((req, res, next) => {
  const ip = req.ip;
  requestCounts[ip] = (requestCounts[ip] || 0) + 1;
  
  if (requestCounts[ip] > THRESHOLD) {
    return res.status(429).send('Too Many Requests');
  }
  next();
});
```

Rate limiting-ஐ கையாள, உங்கள் scraper செய்ய வேண்டியது:

- requests-க்கிடையில் தாமதங்களைச் செயல்படுத்துதல்
- robots.txt வழிகாட்டுதல்களை மதித்தல்
- பெரிய அளவில் scraping செய்யும்போது IP rotation-ஐ பரிசீலித்தல்

### CAPTCHA-கள் மற்றும் தொடர்பாடல் சவால்கள்

CAPTCHA-கள் மனிதர்களுக்கு எளிதான ஆனால் bots-க்கு கடினமான பணிகளை முன்வைக்கின்றன. reCAPTCHA v3 போன்ற நவீன CAPTCHA-கள் பின்னணியில் கண்ணுக்குப் புலப்படாமல் இயங்கி, பயனர் நடத்தைப் பகுப்பாய்வு செய்வதற்கும் பயன்படுகின்றன:

```html
<!-- Example CAPTCHA implementation -->
<form>
  <div class="g-recaptcha" data-sitekey="your-site-key"></div>
  <button type="submit">Submit</button>
</form>
```

CAPTCHA-களைச் சமாளிப்பதில் இவை இருக்கலாம்:

- CAPTCHA தீர்க்கும் சேவைகள் (எனினும் நெறிமுறை சார்ந்த பரிசீலனைகள் பொருந்தும்)
- மனிதனைப் போன்ற நடத்தை உருவகப்படுத்த browser automation-ஐ பயன்படுத்துதல்
- சில உள்ளடக்கங்கள் அணுக முடியாதவையாகவே இருக்கக்கூடும் என்பதை ஏற்றுக்கொள்ளுதல்

### நடத்தைப் பகுப்பாய்வு மற்றும் fingerprinting

மேம்பட்ட பாதுகாப்புகள் mouse நகர்வுகள், scrolling முறைமைகள், மற்றும் சாதன பண்புகளைப் பதிவு செய்து bots-ஐ அடையாளம் காண்கின்றன:

```javascript
// Simplified fingerprinting concept
function collectFingerprint() {
  return {
    userAgent: navigator.userAgent,
    screenResolution: `${screen.width}x${screen.height}`,
    timezone: Intl.DateTimeFormat().resolvedOptions().timeZone,
    language: navigator.language,
    // Many more signals in production systems
  };
}
```

இந்த உத்திகளுக்கு எதிராக செயல்பட வேண்டுமானால்:

- மனிதனைப் போன்ற நடத்தை உருவகப்படுத்தக்கூடிய headless browsers
- தொடர்பாடல் முறைமைகளை சீரற்றதாக மாற்றுதல்
- cookies மற்றும் session data-ஐ தொடர்ந்து ஒரேசீராக நிர்வகித்தல்

### மாறுபடும் உள்ளடக்கம் மற்றும் HTML மறைமுகப்படுத்தல்

பல தளங்கள் JavaScript வழியாக உள்ளடக்கத்தை render செய்கின்றன, அல்லது element ID-களையும் class name-களையும் சீரற்ற முறையில் மாற்றுகின்றன:

```html
<!-- Yesterday's HTML -->
<div class="product-price">$99.99</div>

<!-- Today's HTML after obfuscation -->
<div class="_a7b92f3e">$99.99</div>
```

இதனால் உங்கள் scraper செய்ய வேண்டியது:

- Playwright அல்லது Puppeteer போன்ற முழுமையான browser சூழல்களைப் பயன்படுத்துதல்
- துல்லியமான selectors-ஐ விட உள்ளடக்க முறைமைகளில் கவனம் செலுத்துதல்
- மேலும் நிலைத்த parsing உத்திகளை செயல்படுத்துதல்

## நெறிமுறை மற்றும் சட்ட சார்ந்த பரிசீலனைகள்

இந்த அத்தியாயம் பாதுகாப்புகளை சமாளிக்கும் உத்திகளை அறிமுகப்படுத்தினாலும், கவனிக்க வேண்டியது:

- அளவுக்கு மீறிய scraping website செயல்திறனை பாதிக்கக்கூடும்
- Terms of Service பெரும்பாலும் scraping-ஐ வெளிப்படையாகத் தடைசெய்யும்
- சில நீதித்துறைகளில் அனுமதியற்ற அணுகலைப் பற்றிய சட்டங்கள் உள்ளன

கல்வி நோக்கங்களுக்காக, நாங்கள் பரிந்துரைப்பது:

- production sites-ஐ scrape செய்வதற்கு முன் robots.txt-ஐச் சரிபார்த்தல்
- requests-க்கிடையில் நியாயமான தாமதங்களைச் செயல்படுத்துதல்
- செயல்திறன் முக்கியமானபோது API விருப்பங்களைப் பரிசீலித்தல்
- பொருத்தமான இடங்களில் அடையாளம் காணக்கூடிய user agent-ஐப் பயன்படுத்துதல்

## சவாலை அணுகும் முறை

அத்தியாயம் 11-இல் உள்ள எங்கள் CryptoDefend exchange, நிதித் தரவை சேகரிக்கும் போது நீங்கள் சந்திக்கக்கூடிய நிஜத்தன்மையுள்ள சவால்களை முன்வைக்கிறது. நீங்கள் சமாளிக்க வேண்டியது:

- price API endpoints-இல் rate limiting
- trading data-ஐ அணுக எளிய verification puzzles
- JavaScript வழியாக மட்டுமே render ஆகும் market charts
- வருகைகளுக்கு இடையில் மாறும் சீரற்ற selectors

இந்த செயல்முறைகளைப் புரிந்துகொண்டு, உங்கள் தரவு சேகரிப்பு கருவித்தொகுப்புக்கான நடைமுறை உத்திகளை உருவாக்குவதே குறிக்கோள்.

```typescript
// Example of polite scraping with delays
async function politeScraper(urls: string[]) {
  for (const url of urls) {
    // Check robots.txt first
    if (await isAllowedByRobotsTxt(url)) {
      const content = await fetchWithDelay(url, 2000); // 2-second delay
      // Process content...
    }
  }
}
```

## குறிப்புகள்

1. scrape செய்ய முயற்சிப்பதற்கு முன் தளத்தின் நடத்தையைப் பகுப்பாய்வு செய்வதிலிருந்து தொடங்குங்கள்
2. ஏற்றுக்கொள்ளத்தக்க request rates-ஐ கண்டறிய படிப்படியாக அதிகரிக்கும் தாமதங்களைச் செயல்படுத்துங்கள்
3. API calls-ஐப் புரிந்துகொள்ள Playwright's network inspector போன்ற கருவிகளைப் பயன்படுத்துங்கள்
4. உண்மையான பயனர்கள் தளத்துடன் எவ்வாறு தொடர்புகொள்கிறார்கள் என்பதை கருதி, அந்த நடத்தையைப் பின்பற்றுங்கள்

தொழில்முறை பயன்பாடுகளுக்காக, நீடித்துநிற்கக்கூடிய scraping அணுகுமுறை என்பது தொழில்நுட்பத் தேவைகளையும் தள வரம்புகளையும் சமநிலைப்படுத்துவதாகும். தேவையற்ற தடைகளைத் தவிர்த்து, உங்களுக்கு தேவையான தரவை திறமையாகச் சேகரிப்பதே இறுதி இலக்கு.

```typescript
// A robust scraper implementation includes error handling
async function scrapeCryptoData(url: string) {
  try {
    // Handle rate limits with retry logic
    // Implement dynamic delays when needed
    // Configure appropriate request headers
    const browser = await playwright.chromium.launch();
    const page = await browser.newPage();
    await page.setExtraHTTPHeaders({
      'User-Agent': 'YourProject/1.0 (educational-purposes)'
    });
    
    // Continue with data extraction logic...
  } catch (error) {
    // Implement smart retry logic
    console.error('Extraction error:', error);
  }
```
