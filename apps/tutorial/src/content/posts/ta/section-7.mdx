எங்கள் நடைமுறை வலை ஊர்வு பயிற்சி தொடரின் இறுதி பிரிவிற்கு வரவேற்கிறோம். வழக்கமான பாடமாக இதை அமைப்பதற்குப் பதிலாக, நாங்கள் வேறுபட்ட அணுகுமுறையை எடுத்துள்ளோம். இந்தப் பிரிவிற்காக, நான் Housefly Metascraper-ஐ உருவாக்கியுள்ளேன்—இது `./apps/metascraper` அடைவில் உள்ள ஒரு ஊர்வி; நாங்கள் கற்றதையெல்லாம் நிஜ உலகச் சூழலில் எப்படி பயன்படுத்துவது என்பதை இது காட்டுகிறது.

Metascraper எங்கள் படிப்படியான பயணம்—எளிய static HTML-ஐ scrape செய்வதிலிருந்து, JavaScript-rendered உள்ளடக்கத்தை வழிநடத்துவது, APIs-உடன் தொடர்பு கொள்ளுவது, மற்றும் ஊர்வலைத் தடுக்கப் பயன்படுத்தப்படும் பாதுகாப்புகளை கடப்பது வரை—எப்படி ஒன்றுசேர்ந்து **பெரிய அளவில் கட்டமைப்பற்ற, பல்வகைமையான, குழப்பமான வலை உலகை கையாளக்கூடிய கருவியாக** மாறுகிறது என்பதை விளக்குகிறது.

எதிர்பார்க்க வேண்டிய தரவுக் கட்டமைப்புகள் என்ன என்பதை முன்கூட்டியே அறியாமல், மிகப் பலவிதமான websites-களில் எப்படி ஊர்வது என்பதை நாம் ஆராயப்போகிறோம். அதோடு **AI-உதவியுடன் பகுப்பாய்வு**, **இயங்கும் schema கண்டறிதல்**, மற்றும் **ஆயிரக்கணக்கான (அல்லது மில்லியன் கணக்கான) பக்கங்களுக்கு விரிவுபடுத்தும்** போது அமைப்பு சிதையாமல் இருக்க வேண்டிய நுட்பங்களையும் அறிமுகப்படுத்தப் போகிறோம்.

## "Unstructured" மற்றும் "Large-Scale" என்பதன் உண்மையான பொருள் என்ன?

முந்தைய பிரிவுகளில், நமக்கு பொதுவாகத் தெரிந்திருந்தவை:
- நாம் குறிவைக்கும் sites எவை.
- நமக்கு வேண்டிய தரவு என்ன (உதாரணமாக, tables, lists, JSON responses).
- எத்தனை பக்கங்களைப் பார்க்க வேண்டும்.

ஆனால் பெரிய அளவிலான கட்டமைப்பற்ற ஊர்வலில்:
- websites மிகவும் மாறுபடும்: சில கட்டமைப்புடன் இருக்கும்; மற்றவை ஒழுங்கற்ற வடிவமைப்புள்ள blogs ஆக இருக்கும்.
- paths மற்றும் URLs முன்னறிவிக்க முடியாதவை.
- schema ஒருமித்ததாக இருக்காது, அல்லது இருக்கவே இருக்காது.
- நாம் **ஆயிரக்கணக்கான பக்கங்களை ஊர வேண்டும்**, அதுவும் **பல domains** முழுவதும் இருக்கக்கூடும்.

இதுபோல நினைத்துப் பாருங்கள்:
- கல்விசார் websites முழுவதும் தரவைச் சேகரிக்கும் ஆய்வு ஊர்விகள்.
- குறிப்பிட்ட தலைப்பறிவுக்காக blogs-ஐ index செய்யும் AI assistants.
- முழு பொதுவான இணையத்தையும் பொதுமைப்படுத்திப் புரிந்துகொள்ள வேண்டிய search engines.

இதுவே வலை ஊர்வலின் இறுதி மாபெரும் சவால்.

## பகுதி 1: பெரிய அளவிலான ஊர்வலுக்கான கட்டமைப்பு வடிவமைப்பு

பகுப்பாய்வைப் பற்றி கவலைப்படுவதற்கு முன், உங்கள் ஊர்வியை எப்படி விரிவுபடுத்துவது என்பதைப் பற்றி பேசுவோம்.

### வடிவமைப்பு முறைகள்

பெரிய அளவிலான ஒரு ஊர்வியை உருவாக்க, உங்கள் கட்டமைப்பு இப்படியாக இருக்க வேண்டும்:
- **Queue-driven:** நிலுவையில் உள்ள URLs-ஐச் சேமிக்க ஒரு message queue-ஐ (Redis, RabbitMQ, அல்லது Kafka போன்றவை) பயன்படுத்துங்கள்.
- **Worker-based:** queue-இலிருந்து வேலைகளை எடுத்துச் செயலாக்கும் worker processes-ஆக ஊர்விகளைப் பிரியுங்கள்; அவை தனித்தனியாக jobs-ஐ செயல்படுத்த வேண்டும்.
- **Deduplicated:** அதே பக்கத்தை இருமுறை செயலாக்காமல் இருக்க fingerprint செய்யப்பட்ட ஒரு index-ஐ (உதாரணமாக URL அல்லது HTML content-இன் SHA1) பராமரிக்கவும்.
- **Resumable:** செயலிழப்புகளிலிருந்து மீள crawl state-ஐ நிலையாகச் சேமிக்கவும்.

இதோ ஒரு மிகச் சுருக்கமான வடிவமைப்பு வரைபடம்:

## பகுதி 2: 2025-க்கான முன்னோடியான நுட்பங்கள்

### Residential Proxies

பெரிய அளவிலான scraping துறையில் ஏற்பட்ட மிக முக்கியமான முன்னேற்றங்களில் ஒன்று **residential proxies** பயன்பாடாகும். websites எளிதில் கண்டறிந்து தடுக்கக்கூடிய datacenter IPs-களுக்கு மாறாக, residential proxies உங்கள் requests-ஐ உண்மையான பயனர் IP முகவரிகள் வழியாக அனுப்புகின்றன; இதனால் உங்கள் scraper ஒரு நியாயமான பயனர் போலத் தோன்றுகிறது.

### AI-ஆல் இயக்கப்படும் தன்னாட்சி Agents

2025-இல் மிகப் புரட்சிகரமான முன்னேற்றம் **agentic scraping** ஆகும். ஒவ்வொரு site வடிவமைப்பிற்கும் scrapers-ஐ hard-code செய்வதற்குப் பதிலாக:

- vision திறன்களுள்ள LLMs முன்பு பார்த்திராத layouts-இலிருந்தும் தரவைப் புரிந்து எடுக்க முடியும்
- AI agents மனிதர் உலாவும் நடத்தை மாதிரிகளைப் பின்பற்றி சிக்கலான sites-களில் தன்னாட்சியாகச் செல்ல முடியும்
- adaptive parsing, code updates தேவையில்லாமல் layout மாற்றங்களுக்கு தானாகச் சீரமைந்து கொள்ளும்

## பகுதி 3: AI-உதவியுடன் பகுப்பாய்வு

சுத்தமான JSON வெளியிடும் வகையில் ஒரு model-ஐ fine-tune செய்யவும் அல்லது prompt-engineer செய்யவும்:

```json
{
  "name": "Dr. Maria Lopez",
  "title": "Climate Scientist",
  "organization": "Stanford",
  "topic": "2023 UN Climate Summit, AI in climate modeling"
}
```

## பகுதி 4: தரவைச் சேமித்தல், Index செய்தல், மற்றும் தேடல்

நீங்கள் **மிக அதிக அளவில் பல்வகைத் தரவை** சேகரிப்பீர்கள். உங்கள் இலக்குகளையும் தரவு எவ்வளவு கட்டமைப்புடனுள்ளது என்பதையும் அடிப்படையாகக் கொண்டு சேமிப்பு முறையைத் தேர்வுசெய்யுங்கள்.

### சேமிப்பு உத்திகள்

- **PostgreSQL** அல்லது **SQLite**: schema தெரிந்த கட்டமைக்கப்பட்ட அட்டவணைத் தரவுக்கு சிறந்தவை (உதாரணமாக articles, prices, timestamps). indexes, foreign keys, மற்றும் full-text search (FTS) பயன்படுத்தலாம்.
- **MongoDB** அல்லது **Elasticsearch**: பதிவுகளுக்கு இடையில் schema மாறக்கூடிய JSON blobs போன்ற அரை-கட்டமைப்புடைய அல்லது நெகிழ்வான தரவு வடிவங்களுக்கு மிகச் சிறந்தவை.
- **S3 / IPFS / File System**: raw HTML snapshots, images, PDFs, மற்றும் பெரிய binary files-களுக்கு மிகவும் ஏற்றவை. metadata-வை database-இல் சேமித்து, file location-க்கு இணைக்கவும்.

முன்னர் ஊரப்பட்ட உருப்படிகளை deduplicate செய்யவும் கண்காணிக்கவும், primary keys ஆக UUIDs அல்லது URL hashes-ஐப் பயன்படுத்துங்கள்.

### தேடக்கூடியதாக மாற்றுதல்

ஒருமுறை சேமித்த பிறகு, அந்த உள்ளடக்கத்தை **ஆராயவும் query செய்யவும்** நீங்கள் விரும்புவீர்கள்.

விருப்பங்கள்:

- **PostgreSQL FTS (Full-Text Search)**: `tsvector` மற்றும் `tsquery` பயன்படுத்தி ranking உடன் வலுவான keyword search திறன்களை அமைக்கலாம்.
- **Typesense** அல்லது **Meilisearch**: வேகமான indexing மற்றும் fuzzy search-க்கு மிகவும் ஏற்ற, எடை குறைந்ததும் schema-இல் நெகிழ்வானதும் ஆன full-text search engines.
- **Elasticsearch**: அதிகச் சிக்கலான தேடல் பயன்பாடுகள் அல்லது logs-களுக்கு சிறந்தது; சக்திவாய்ந்த filtering மற்றும் analytics வசதிகளுடன்.

நீங்கள் index செய்ய வேண்டிய fields:
- தலைப்பு
- ஆசிரியர்
- வெளியிடப்பட்ட தேதி
- keywords அல்லது tags (extract செய்திருந்தால்)
- முதன்மை உள்ளடக்கம்
- domain / மூலம்

### Embeddings மூலம் பொருள்சார் தேடல்

மேலும் ஆழமான புரிதலும் மீட்டெடுப்பும் (keywords-ஐத் தாண்டி) வேண்டுமெனில், **text embeddings** பயன்படுத்துங்கள்:

1. OpenAI-யின் `text-embedding-3-small` போன்ற model-ஐ அல்லது `bge-small-en` போன்ற open-source மாற்றுகளைப் பயன்படுத்துங்கள்.
2. நீங்கள் ஊர்ந்துள்ள உள்ளடக்கத்தை embedding vectors-ஆக மாற்றுங்கள்.
3. அவற்றை ஒரு **vector database**-இல் சேமியுங்கள், உதாரணமாக:
   - **Qdrant**
   - **Weaviate**
   - **Pinecone**
   - **FAISS** (local / in-memory பயன்பாட்டிற்கு)

இது போன்ற semantic queries-ஐச் செயல்படுத்த முடியும்:
> "குளிரான காலநிலைகளில் மிதிவண்டி நட்பு நகர வளர்ச்சி பற்றி யாராவது பேசும் கட்டுரைகளை எனக்குக் காட்டு."

query embedding-ஐ சேமிக்கப்பட்ட embeddings-உடன் ஒப்பிடுவதன் மூலம், உங்கள் crawler ஒரு அறிவு இயந்திரமாக மாறுகிறது.

### Metadata மற்றும் செறிவூட்டல்

இறுதியாக, உங்கள் தரவுக்கு கூடுதல் metadata-ஐச் சேர்த்து செறிவூட்டுங்கள்:

- **Language detection** (`langdetect` அல்லது fastText போன்றவற்றுடன்).
- zero-shot models அல்லது fine-tuned classifiers பயன்படுத்திய **உள்ளடக்க வகைப்பாடு**.
- மனிதர்கள், நிறுவனங்கள், மற்றும் இடங்களை extract செய்ய **Named Entity Recognition (NER)**.
- உள்ளடக்கம் அல்லது மூலம் அடிப்படையிலான **Geotagging**.

பின்னர் filter செய்து sort செய்ய இது உதவும் என்பதால், இதையும் முதன்மைத் தரவுடன் சேர்த்து சேமியுங்கள்.

## பகுதி 5: தேடல்-மையப்படுத்தப்பட்ட கண்டறிதல் ஊர்விகள்

பெரிய அளவிலான ஊர்வலுக்கான மிக மேம்பட்ட அணுகுமுறை URLs-இலிருந்து கூட தொடங்காது—அதற்குப் பதிலாக, அது **தேடல் queries**-இலிருந்து தொடங்குகிறது.

SearchXNG மற்றும் Perplexity போன்ற கருவிகளால் தூண்டப்பட்ட Metascraper, தேடல்-முதன்மை உத்தியை வெளிப்படுத்துகிறது; அதில் crawler:

1. seed URL பட்டியலுக்குப் பதிலாக ஒரு **தலைப்பு அல்லது கேள்வி**யிலிருந்து தொடங்குகிறது
2. தொடர்புடைய பக்கங்களை real-time-இல் கண்டறிய search engine APIs-ஐப் பயன்படுத்துகிறது
3. search results அடிப்படையில் தனது crawl queue-ஐ இயங்கும் வகையில் உருவாக்குகிறது
4. அறிவை விரிவாக்க citations மற்றும் references-ஐ நுண்ணறிவுடன் பின்தொடர்கிறது

இந்த அணுகுமுறை பல நன்மைகளை வழங்குகிறது:

- **இலக்கு மையப்பட்ட ஆராய்ச்சி**: முழுமையாக எல்லாவற்றையும் ஊர்வதற்குப் பதிலாக, தொடர்புடைய தகவல் இருக்கக்கூடிய பக்கங்களையே பார்வையிடுகிறீர்கள்
- **நேரத்துக்கு ஏற்ற முடிவுகள்**: ஒவ்வொரு crawl-உம் சமீபத்திய search results-உடன் புதிதாகத் தொடங்குகிறது
- **Domain-agnostic**: முன்கூட்டியே வரையறுக்கப்பட்ட sites அல்லது URL patterns-களால் கட்டுப்படுத்தப்படாது
- **நோக்கம் வழிநடத்துவது**: மனிதர்கள் உண்மையில் தலைப்புகளை ஆய்வு செய்வது போலவே இது அமைந்துள்ளது

Metascraper-இன் search-driven mode, நீங்கள் எந்த URLs-ஐப் பார்க்கப் போகிறீர்கள் என்பதை முன்கூட்டியே அறியாமலேயே, search APIs, prioritization algorithms, மற்றும் context-aware extraction ஆகியவற்றை ஒன்றுசேர்த்து, இயங்கிக்கொண்டே கண்டறியப்படும் உள்ளடக்கத்திலிருந்து knowledge graphs உருவாக்குவது எப்படி என்பதை காட்டுகிறது.
